# v0.3.5 — 2026-09-06

One change, in two carriers: `self_correcting` leaves the supervision contract
entirely. It was the judge's second question — *would the actor come back by
itself* — and a `true` answer used to withhold the correction. #432 demoted it
to recorded-but-never-acted-on in the Python carrier; 0.3.4 shipped it in that
state so the question of deleting it could be answered from downstream data
rather than taste. That data came back, and
[ADR-0022](../decisions/ADR-0022-self-correcting-leaves-the-verdict.md) removes
the field outright.

**There is nothing else in this release for a consumer to react to.** The only
other commits since v0.3.4 (#437, #439) change agent-facing repo rules and a
local data path; no runtime behavior moves with them.

This release is numbered `0.3.5`. Which digit a swe-lab release moves is not
inferred from what changed — it is fixed by
[`conventions.md` → Which digit moves](../conventions.md#which-digit-moves).

Raw commit list: the GitHub Release's generated notes.

## Breaking

### 1. `self_correcting` is gone from the supervision contract, and an answer still carrying it is unusable (#438, #440, [ADR-0022](../decisions/ADR-0022-self-correcting-leaves-the-verdict.md))

**What changed.** The field leaves every surface it occupied, in both carriers
of the supervision stack:

| Surface | v0.3.4 | v0.3.5 |
|---|---|---|
| Judge tool schema (`JUDGE_TOOL`, Python) | in `properties` and `required` | absent; `additionalProperties: false` rejects it |
| `Verdict` (`trace_synthesis.supervisor`, Python) | `self_correcting: bool` | field removed |
| `Verdict` (`model.rs`, Rust) | `pub self_correcting: bool` | field removed |
| Judge answer shape (Rust `JUDGE_INSTRUCTIONS`) | `{"off_track", "self_correcting", "reason"}` | `{"off_track", "reason"}` |
| Default judge instruction texts | "Decide two things" + the field's line | "Decide one thing"; the line is gone |
| Supervisor and segmented-loop decision rows | `"self_correcting": …` | key absent |
| The writer's structured verdict block | carried the field | does not |
| Guidebook rubric contract | six fields | five |

A judge answer that **still sends the field is now an unusable judge answer**,
which the policy records as one bounded lapse — one judge call, no writer call,
the next boundary judged normally. Both carriers enforce it independently:
Python by `additionalProperties: false` plus a local decoder check
(`unusable judge answer: unexpected tool input fields: self_correcting`), Rust
by an allow-list of `{off_track, reason}` in its own parser
(`unusable judge answer: unexpected fields: self_correcting`). **There is no
compatibility switch and no deprecation period.**

**Why.** Downstream results on 0.3.4 — the first release carrying the demoted
field — answered the question ADR-0021 was holding it open for. A
recorded-but-unused field is not free: it is a required output of every judge
call, so it spends tokens and instruction budget on an answer that is
discarded; it appears in every decision row, where a reader has to be told to
ignore it; and it keeps a rubric section in every guidebook whose only purpose
is to explain it.

Rejecting rather than ignoring the stale field is the deliberate half. Silently
discarding it would make a provider answering under the old schema and one
answering under the new produce indistinguishable verdicts — the observation
would have no power to separate them, which is exactly what makes it worthless
as a check.

**What you must do.** This one **raises** rather than doing the wrong thing
quietly, but it raises as a *lapse*, not as a crash: a run whose provider still
emits the field will complete while producing no verdicts at all, so the
failure is loud in the supervision log and silent in the exit status. Check for
it before a batch, not after.

- **Custom judge instructions** (`ModelJudge.instructions`,
  `supervising_policy(instructions=...)`) that ask for the field: delete the
  request. The model will otherwise keep answering with it.
- **A mock or synthetic transport** that returns a canned verdict: drop the key
  from the canned answer. This is the most likely place to be bitten — a test
  double written against 0.3.4 now turns every boundary into a lapse.
- **A gateway that pins the pre-removal tool schema**: re-point it, or it will
  keep advertising a field the decoder refuses.
- **Scripts reading decision rows** (supervisor or segmented-loop logs): treat
  the key as absent. Read it with a default rather than by subscript, and do not
  branch on it — the gate it once fed is gone.

### 2. The Rust supervisor speaks where it used to stay silent (#440)

**What changed.** In `rust/swe-lab-supervisor/`, the speak gate was

```rust
if !verdict.off_track || verdict.self_correcting { /* silent */ }
```

and is now

```rust
if !verdict.off_track { /* silent */ }
```

`off_track` is the only field that opens the gate. Everything after it — the
would-have-spoken marker, budget, cooldown, cancellation, the writer's own
bounds — is unchanged.

**Why.** The Rust runtime is the second carrier of the same supervision stack
and never received #432's demotion, so it kept the second veto live for three
releases after the Python path dropped it. This is the alignment, not a new
decision: #432 settled the gate, ADR-0022 settled the field.

**What you must do.** Expect **a higher intervention rate from the in-sandbox
native supervision runtime**, on unchanged inputs and an unchanged
configuration. A boundary where the judge says the actor is off track and
returning by itself now produces a correction where 0.3.4's binary produced
silence. Nothing raises and nothing is logged as a change; the run simply
speaks more, and costs more writer calls.

Results from the native runtime are therefore **not comparable across this
version boundary**. Re-baseline rather than compare. The Python host-side
supervisor — the default, and what `oracle_guided_trace` and
`segmented_rollout_and_unit_test` use — has behaved this way since 0.3.4 and
does not move here.

## Compatibility

**A six-field guidebook still validates.** Rubric validation is presence-checked
per field, so a guidebook written under ADR-0021 — carrying
`Self-correction signals` as a sixth section — still validates, is still
delivered to the supervisor whole, and no stored artifact is invalidated. Only
new phase-B output is written with five.

**The frozen `n_batching_replay` records keep the field.** It is a legacy column
there: `analyze.py` reads it where present, so that experiment's committed
`judgments.jsonl` and the numbers in its `REPORT.md` remain reproducible, and
rows recorded after the removal fall through to the `off_track`-only gate.

  the change: restoring the field to the accepted set turns the
  answer-is-unusable tests red, and restoring the two-veto gate turns the
  speaks-anyway tests red. A test that passes only because the condition it
  guards cannot arise is not a gate, and neither of these is that.
- **No supervised rollout was run for this release**, and no effect of the
  higher intervention rate is claimed or measured. What is established is the
  contract change and its gates — not what it does to a solve rate.
