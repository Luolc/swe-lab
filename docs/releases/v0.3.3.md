# v0.3.3 — 2026-09-05

## Typed judge verdicts, a swappable judge prompt, and the gates 0.3.1 shipped without

### Breaking

- **The judge no longer parses free-form JSON text.** `ModelJudge` forces one
  `submit_supervision_verdict` tool call, requires **exactly one** matching
  `tool_use` block, and builds its `Verdict` from typed input. There is no text
  fallback. A custom transport or gateway that returns a text-only answer, no
  tool call, a differently named tool, or two matching tool calls now produces
  an unusable-answer lapse rather than a verdict.

  The declared schema is the provider's promise, not this code's check: since
  `0.3.2` the base URL belongs to the caller, so every shape rule is validated
  locally and the tests feed malformed `tool_use` input through a synthetic
  transport rather than relying on an endpoint to refuse it.

- **A present but non-integer, non-null `deviation_started_steps_ago` is now a
  lapse**, where it was silently dropped. Absent is still fine. `bool` is
  rejected: it subclasses `int` in Python, so a judge answering `true` would
  otherwise be recorded as "1 step ago".

- **A missing or structurally invalid guidebook is refused before the actor
  starts**, instead of falling back in silence to the general criterion. A
  guided workflow that could previously run un-guided now fails loudly. This is
  the point: a silent fallback produces a trace indistinguishable from a
  correctly guided one.

- **`max_cost_usd` caps cumulative spend.** It compared the latest segment's
  cost, so the documented ceiling was never a budget. A run that stayed under it
  by accident may now stop where it did not before.

### Added

- **`ModelJudge.instructions` and `supervising_policy(instructions=...)`** take a
  replacement judge prompt verbatim, so a prompt sweep can compare pass rates
  without editing a module-level constant. `None` keeps the existing
  guided/unguided selection byte-for-byte. No registry, hashing or persistence
  comes with it — the substituted text already reaches the record through the
  existing `judge_input` provenance.
- **`--rollout.harness.segmented.cooldown`** joins the four knobs `0.3.1`
  exposed, and is observed reaching the policy factory rather than resting in a
  configuration object.
- **The `oracle_failures` builder accepts a baseline-patched run**, rather than
  refusing everything the ADR-0014 default produces. The recorded base ref rides
  in the existing provenance, is mounted at load, and restores the source
  grading contract. Legacy seven-column rows still load.
- **Four shallow checks bound what the supervisor may say** — length, fenced
  code, a diff hunk, and an eight-word copy out of the guidebook — each with an
  independent rejection arm and an acceptance arm proving a short directional
  hint and an inline file reference still pass.

  They are a floor, not proof of non-leakage, and the wording claims only the
  shapes they actually reject. Semantic paraphrase is not detected, and "the
  writer never reveals the answer" is deliberately **not** stated as an
  invariant.
- **That the guidebook never enters the actor's context is now a test.** The
  naive form of that check does not work: the guidebook restates the task and so
  does the actor's prompt, so shared text is not leakage — on the first
  end-to-end run all 150 shared twelve-word shingles came from the task prompt
  and none was a leak. The test subtracts task-prompt shingles and carries both
  a shared-source control and a guidebook-only contamination control.

### Fixed

- **A baseline row staged its base ref and never consumed it.** The row compiled
  a `patch_baseline=True` script while the Oracle task composed no baseline
  verify or reset, so a failed patch landed on a fresh base-commit tree and
  still produced an ordinary-looking score — the wrong grading contract,
  silently.
- **Two writer-gate bypasses**: a fenced block nested in a blockquote, and Git's
  combined-diff `@@@` header where only unified `@@` was recognized.

### Decisions

ADR-0018 is **Accepted**: the supervisor reads the guidebook in full, and the
boundary is on what it says rather than on what it sees. The spec sections it
supersedes are rewritten. Success Criterion 2 stays withdrawn — a runnable
workflow is mechanism availability, not evidence that steering has value.

### Known gaps

Still open, and worth knowing before reading a supervision run: the judge's
prompt renderer drops tool results the evidence filter admits (#380), every
judge lapse observed so far was `max_tokens` exhausted by reasoning tokens
(#383), and the supervisor's own corrections drive its judge (#381). A run in
which the supervisor rarely speaks may be measuring any of these rather than a
conservative judge.
