# v0.3.4 — 2026-09-05

## The supervisor sees complete evidence, carries state, and speaks when the actor is off track

This is the largest behavioral release of the supervision path so far. If you
run supervision, read the breaking list — the judge's input, its required
output, and the condition under which it speaks have all changed.

### Breaking

- **The judge is now shown complete, paired evidence, and the default prompt
  changes accordingly.** The renderer kept `TextBlock` and dropped every
  `ToolUseBlock` and `ToolResultBlock` — which is why #380 measured 11 of 90
  records rendering non-empty — and the evidence window sliced by raw record
  count, which could cut a tool call away from its result. Selection now takes
  complete assistant turns and never separates a call from its result; a
  genuinely missing result is marked rather than passed over. Reasoning blocks
  are dropped, visible assistant text is configurable, and oversized values are
  bounded **with the truncation stated** while the complete value stays on disk.

  Prompt-level byte-identity no longer holds for rendered evidence, and cannot:
  #380 is a defect report, so its fix has to be the default. What does still
  hold is byte-identity of instruction text and of the Oracle and writer
  requests.

- **`running_state` is a required judge output.** The judge returns a bounded
  running state alongside its verdict, in the same tool call — not a second
  model call. It is handled by the rules #425 set for every other verdict
  field: no fallback, no retry, one bounded lapse. A response without it is
  unusable.

- **The judge now sees only the just-completed segment**, not the accumulated
  window. What leaves the prompt is carried by the running state, which the
  policy advances after each valid verdict.

- **`self_correcting` no longer vetoes an intervention.** `off_track` is the
  only gate on speaking. **This raises the intervention rate**, by design: a
  field whose stated job was restraint, in a supervisor that rarely spoke, was
  the first thing to question. It remains in the schema, the prompt and the
  telemetry — recorded, never acted on — so the question of deleting it can be
  answered from data rather than taste.

- **A present but malformed guidebook rubric is refused before the actor
  starts.** A completely absent one is not: see the compatibility note below.

### Added

- **A compact supervisor-facing guidebook rubric** — checkpoints, on-track
  evidence, disallowed branches, off-track signals, self-correction signals and
  a safe hint justification — written *alongside* the detailed tutorial, not in
  place of it. The default prompt builder sends the judge and writer only the
  rubric; a replacement `PromptBuilder` still receives the complete guidebook,
  and the full tutorial stays in the persisted artifact.
- **Selector, renderer and prompt builder are public components** with a default
  composition, so a custom policy can replace one without reimplementing the
  segmented loop, intervention validation or logging.
- **`ModelWriter.instructions` and an Oracle instructions override**, matching
  `ModelJudge.instructions` from 0.3.3. `None` keeps the existing selection
  byte-for-byte, and no prompt registry comes with them.
- **Silent decisions record their verdict.** A boundary where the judge answered
  "on track" and one where it produced nothing were previously indistinguishable
  in the log — both are simply an absence of intervention. `off_track`,
  `self_correcting` and `reason` are now recorded for silent and speaking
  decisions alike.
- **Which guidebook mode a run used is recorded** as `rubric`,
  `legacy_tutorial` or `null`. An optional field forks behavior silently: a run
  steered by a rubric and one that fell back to the tutorial produce traces that
  look identical, so a batch comparison would be contaminated invisibly and a
  prompt sweep would attribute the difference to the prompt.

### Fixed

- **`ModelWriter` selects its text block** instead of reading
  `content[0]["text"]`, so a response with a thinking block before its text no
  longer becomes a lapse while the requested line sits in the response. The raw
  content and `stop_reason` are recorded *before* extraction, so they survive
  the failure case rather than being lost exactly when someone would want them.

### Compatibility

The guidebook rubric is required of new phase-B output and optional on read.
That is not a convenience: `Workflow.execute(resume=True)` — the programmatic
default — trusts an existing terminal marker and re-stages the already-persisted
`guidebook.md`, so requiring a rubric unconditionally would make a supported
path refuse its own artifact. The absence of such a guidebook in any local
inventory is deliberately not the argument; "no instance here" and "no such
path" agree today and diverge later. ADR-0021 names the exit condition: the
field tightens to required once every supported resume source is rubric-aware or
migrated.

### Known gaps

`#381` remains open — the supervisor's own corrections drive its judge, with
`off_track` going from 0/6 to roughly 80% the moment it speaks. With `#380`
fixed and silent verdicts now recorded, a run's supervision log can finally be
read directly rather than inferred.
