# v0.2.14 — 2026-08-26

The release that makes swe-lab a **two-dataset harness**: DeepSWE 1.1 lands as
a fully runnable dataset — `--dataset deepswe` anywhere `swebench_pro` works —
validated by a full 113-task golden sweep and live agent rollouts, including a
solved task. Around it, three behavior fixes that change what every rollout's
container looks like: `HOME` now defers to the image, each agent's config is
pinned to its own directory, and every engine git command carries a scoped
`safe.directory` grant.

One small breaking change (a moved module), two behavior changes worth
reading before comparing results across versions.

Raw commit list: the GitHub Release's generated notes.

---

## Breaking

### 1. `swebench_pro.verify` moved to `datasets.verify` (#243)

**What changed.** The golden-verification tool generalized to any registered
dataset and moved out of the swebench_pro package:

```
python -m swe_lab.datasets.swebench_pro.verify ...   # gone — ImportError
python -m swe_lab.datasets.verify --dataset <name> ...
```

**Why.** The engine (stride shards, base+golden double-run, classification,
aggregate) was never dataset-specific; what genuinely differs shrank to two
evidence hooks — how "a bug test already passes at base" is detected
(SWE-Bench Pro verdicts name passed tests; DeepSWE's carry only counts) and
what makes a verdict conclusive (`output_state` vs. a grader that raises).

**What you must do.** Update the module path and add `--dataset`. Flags are
otherwise unchanged, and SWE-Bench Pro report fields are byte-compatible with
every earlier sweep report. The `verify-golden.yml` workflow gained a
`dataset` choice input.

## Behavior changes (no API moved — but containers behave differently)

### 2. `HOME` defers to the image; agent config is pinned (#240, #242, #245)

Every harness used to run its agent under an unconditional
`HOME=/agent-home`. That one variable was carrying two unrelated jobs, and
the release splits them:

- **HOME → the image's**, resolved through the same three tiers the eval
  script always used (image value → passwd entry → `/tmp/agent-home`).
  Measured motivation: DeepSWE images pre-warm toolchain caches under their
  HOME (55 MB go-build + 73 MB module cache on one image), and an offline
  agent phase cannot refill a cold one.
- **Config → pinned per agent** to the fresh `/agent-home` via each CLI's own
  variable: `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `GROK_HOME`. Probed per agent
  that pinning **replaces** the `$HOME` path rather than augmenting it — a
  planted `$HOME/.claude/CLAUDE.md` instruction is not read, a decoy
  `$HOME/.grok` login is not consulted, and real credentials left only in
  `$HOME/.codex` are invisible once pinned. The injection isolation the old
  override provided silently is now provided deliberately.

**Watch for:** agents now see the image's real `HOME` (warm caches, faster
and offline-viable builds), so agent behavior — and therefore results — can
shift on cache-sensitive tasks. Regressions on both benchmarks were green
(SWE-Bench Pro codex chain 1.0; DeepSWE claude_code chain 1.0). A custom
composition that relied on `$HOME` being `/agent-home` should read the agent's
config location from the pinned variables instead.

### 3. Engine git commands carry a scoped `safe.directory` grant (#244, #247)

Config isolation (`GIT_CONFIG_GLOBAL=/dev/null` …) had disabled the only
channel for git's `safe.directory` exception — so on an image whose repo is
owned by a different UID than the process running git, extraction, the
history purge and the pre-agent baseline all failed with "dubious ownership",
none of them naming the cause. Every engine git command now runs under one
shared env (`isolated_git_env`): the isolation set plus a `safe.directory`
grant scoped to the instance's checkout (never `*`), delivered as git's
env-config triple, which survives the isolation. Per-invocation — nothing
persists for the agent to observe.

Also uniform now: the **baseline** git commands, which previously ran with no
isolation at all (an image `~/.gitconfig` could have skewed the baseline
while extraction was isolated), and `GIT_TERMINAL_PROMPT=0` everywhere.
Baseline shas are unaffected — the env never enters the commit object,
re-verified byte-identical on a real image.

**Watch for:** runs on ownership-mismatched images that previously failed
with confusing errors now just work; nothing else should move.

## Added — DeepSWE 1.1, end to end (#235–#241, task-30)

- **The dataset**: `load_dataset("deepswe")` / `--dataset deepswe` — 113
  original long-horizon tasks (Datacurve), 5 languages, per-task images on
  public ECR. Instances slot into every existing workflow: `rollout`,
  `unit_test`, `gold_unit_test`, `rollout_and_unit_test`.
- **Distribution**: a self-built parquet on the public HF repo
  [`luolc/deep-swe-1-1-materialized`](https://huggingface.co/datasets/luolc/deep-swe-1-1-materialized),
  built by `python -m swe_lab.datasets.deepswe.build_parquet` from a pinned
  upstream commit. The loader auto-fetches it and **verifies the sha256
  against the in-repo pin on every load** — an HF repo is mutable, like a
  docker tag, so the trust anchor lives in the consumer. A `manifest.json`
  beside the artifact carries provenance, the fixes applied (three
  abbreviated `base_commit_hash` values normalized, verbatim column kept),
  and a per-task content hash that survives parquet re-encoding.
- **Grading**: Datacurve's verifier runs **verbatim** — their four `tests/`
  files mounted at their upstream paths, the candidate patch staged where
  their grader reads it, `reward.json` read back. swe-lab's entryscript
  contains no git at all; their grader owns patch application (per-file
  resets included). `patch_baseline` is refused loudly for this dataset — its
  grader consumes `base_commit`-relative patches only.
- **Attribution maps 1:1**: their `apply_failed` grades zero (the patch's
  fault); their crash sentinel (missing `reward.json`) fails the attempt
  ungraded and retryably.
- Licensing: two-layer (Apache-2.0 + 91 permissive upstream licenses),
  attribution and `PROVENANCE.md` travel with the published data.

## Verified

- **Full 113-task golden sweep** on GitHub Actions (native amd64, 16 shards,
  ~25 min): **0 GOLDEN_FAIL, 0 BASE_UNEXPECTED_PASS**; 109 OK + 4 base-run
  infra flakes whose golden halves were perfect and whose base halves
  re-verified locally as the expected failure.
- **Golden self-checks** via the real CLI in all 5 languages, including the
  task whose 39-char truncated sha the normalization fixes (f2p 84/84).
- **Live rollouts** through `rollout_and_unit_test`: claude_code **solved**
  `abs-stepped-slices` (1.0, f2p 6/6 + p2p 6/6), near-missed `cattrs-…`
  (f2p 67/69, partial 0.97); codex chain complete on a third task.
- **Dirty-worktree census** over all 113 images: 112 clean (cleanliness is
  engineered upstream — 37 Dockerfiles assert porcelain-clean), one image
  with a single uncommitted line; recorded in task-30 with its consequences.
- Post-change regressions: both benchmarks' full chains green under the new
  HOME semantics; the ownership-mismatch container runs all four git scripts
  clean; suite at 652 passed / 3 skipped.
