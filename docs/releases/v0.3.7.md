# v0.3.7 — 2026-09-08

**The segment loop is now the only supervised carrier.** Every other route to
a supervised rollout was removed, on the owner's ruling of 2026-09-08
([ADR-0025](../decisions/ADR-0025-the-segment-loop-is-the-only-supervised-carrier.md),
[ADR-0026](../decisions/ADR-0026-the-correction-channel-is-removed.md)) — the
Rust `swe-lab-supervisor` crate and the in-sandbox native carrier, the
correction channel and the streaming `Supervisor`, and the three workflow
names that ran them. If you were on any of those, **there is no upgrade path
other than moving to the segmented route**; a shim was not built, and the
sections below say what to write instead.

Four PRs (#448, #449, #450, #452) removing about 22,900 lines against 2,900
added — roughly a net −20,000, and the largest breaking release this project
has cut. Nothing removed was failing. The reason given for the removals is
Occam: one carrier, and the simplest code that runs it.

The rest is the guidebook pipeline learning to survive its own first live
runs (#452,
[ADR-0027](../decisions/ADR-0027-the-oracle-writes-a-guidebook-either-way.md)):
the schema stopped rejecting guidebooks and started only measuring them, and
the Oracle's brief stopped hard-coding that the attempt it explains had
failed.

This release is numbered `0.3.7`. Which digit a swe-lab release moves is not
inferred from what changed — it is fixed by
[`conventions.md` → Which digit moves](../conventions.md#which-digit-moves),
and no size of diff moves the middle number.

Raw commit list: the GitHub Release's generated notes.

## Which route you were on

| If you ran | It is | Run instead |
|---|---|---|
| `supervised_rollout_and_unit_test` | gone (#450) | `segmented_rollout_and_unit_test` |
| `control_rollout_and_unit_test` | gone (#450) | no shipped control arm; see §4 |
| `native_supervised_rollout_and_unit_test` | gone (#449) | `segmented_rollout_and_unit_test` |
| `segmented_rollout` / `segmented_rollout_and_unit_test` | unchanged in name | — |
| `oracle_guided_trace` / `from_scratch_guided_trace` | unchanged in name | — |

Every surviving name is still registered and `python -m swe_lab run --list`
still enumerates them. A removed name is refused where the command line is
read, as a bad argument — this one is loud.

## Breaking

### 1. The native carrier is gone, and the Rust crate with it (#449, [ADR-0025](../decisions/ADR-0025-the-segment-loop-is-the-only-supervised-carrier.md))

**What changed.** The whole in-sandbox wrapper route:

- the crate `rust/swe-lab-supervisor` — source, tests, gates and the CI job
  that built and uploaded its static musl artifact;
- `swe_lab.trace_synthesis.native_supervision` (the module, with
  `NativeSupervision`, `NativeSupervisionObserver`, `Blocking`,
  `TerminalSummary`, `UnusableSummary`, `read_terminal_summary`,
  `supervision_metrics`, `API_KEY_ENV`, `BASE_URL_ENV`, `CRITERION_NAME`,
  `SUPERVISOR_BINARY_AT`, `SUPERVISOR_CONFIG_NAME`, `SUPERVISOR_SUMMARY_NAME`,
  the config/summary schema constants and the two native supervision metrics);
- `swe_lab.trace_synthesis.supervisor_binary` (`ensure_supervisor_binary`,
  `supervisor_version`, `binary_cache_path`, `local_build`, `BINARY_ENV`);
- `swe_lab.trace_synthesis.transcript_marks`, which went along as a separate
  find — nothing under `src/` imported it;
- on `ClaudeCodeHarness`: the field `native_supervision` and the whole
  `supervisor_proxy_*` family — `supervisor_proxy_target`,
  `supervisor_proxy_port`, `supervisor_api_key_env`,
  `supervisor_proxy_log_name`, `supervisor_proxy_stderr_name` — plus the
  workspace-name constants behind them (`SUPERVISOR_PROXY_LOG_NAME`,
  `SUPERVISOR_PROXY_STDERR_NAME`, `SUPERVISOR_INFO_NAME`,
  `SUPERVISOR_STDERR_NAME`, `DEFAULT_SUPERVISOR_PROXY_PORT`,
  `SUPERVISOR_FLAGS`);
- the definitions `NATIVE_SUPERVISED_ROLLOUT`,
  `NATIVE_SUPERVISED_ROLLOUT_AND_UNIT_TEST`, `NATIVE_JUDGE_EVERY_N`, and the
  registered workflow `native_supervised_rollout_and_unit_test`.

**Why.** It was a second implementation of something there is now one good
implementation of, and carrying two cost a reader's attention on every change
to either. ADR-0025 supersedes no accepted ADR, because the native carrier
never had one — its design lived in an issue and two task plans.

**What you must do.** Move to `segmented_rollout_and_unit_test` (§4's
migration is the same one). **This raises**, in all three of its shapes: an
unknown workflow name is a bad argument, `ClaudeCodeHarness(...)` with a
removed keyword is a `TypeError`, and an import of a deleted module is an
`ImportError`. There is no silent-wrong-thing window here.

### 2. The correction channel and the streaming `Supervisor` are gone (#450, [ADR-0026](../decisions/ADR-0026-the-correction-channel-is-removed.md))

**What changed.**

- `swe_lab.trace_synthesis.channel` — the whole module: `supervision`,
  `SupervisedRun`, `SupervisorPump`, `CorrectionChannel`, `BindMounted`,
  `stream_events`, `JOIN_TIMEOUT_SECONDS`;
- from `swe_lab.trace_synthesis.supervisor`: the `Supervisor` class, the
  `Sink` protocol, the policies `NeverSpeak`, `SpeakAt` and `WouldHaveSpoken`,
  and `EvidenceFilter` with its disposition constants (`ADMITTED_ASSISTANT`,
  `ADMITTED_TOOL_RESULT`, `EXCLUDED_OWN_INTERVENTION`,
  `EXCLUDED_EXTERNAL_TEXT`, `EXCLUDED_NOTHING_TO_KEEP`). What survives of that
  module is the vocabulary the segment loop imports: the `SpeakPolicy`
  protocol, the verdict, `Observation`, `SaidVisibility`, the log kinds and
  the writer. `EvidenceFilter`'s admission rule did not go — it became a
  private function beside `evidence_of`, which still runs through it;
- on `ClaudeCodeHarness`: the field `correction_channel`, and the workspace
  names behind it (`CORRECTION_FIFO_NAME`, `CORRECTION_DONE_NAME`,
  `CORRECTION_DROP_NAME`, `CORRECTION_RELAY_LOG_NAME`,
  `CORRECTION_UNCLEAN_NAME`);
- on the composition layer: `swe_lab.rollout.SupervisionFactory`, the
  `CodingAgentTask.supervision_factory` field with the `__post_init__` that
  refused a supervised run the actor could not hear, and the
  `Harness.accepts_corrections` property it asked;
- the definitions `SUPERVISED_ROLLOUT`, `CONTROL_ROLLOUT`,
  `SUPERVISED_ROLLOUT_AND_UNIT_TEST`, `CONTROL_ROLLOUT_AND_UNIT_TEST` and
  `CONTROL_BUDGET`, and the registered workflows
  `supervised_rollout_and_unit_test` and `control_rollout_and_unit_test`.

**Why.** The same ruling as §1, applied to its second stage. ADR-0026
supersedes [ADR-0013](../decisions/ADR-0013-supervision-on-the-stdin-channel.md)
(supervision is delivered on the harness's stdin channel) as a **retirement,
not a refutation**: neither of the two things ADR-0013 named as overturning it
happened. The channel goes because one carrier is enough.

**What you must do.** Run `segmented_rollout_and_unit_test`, and build your
own policy through the segment loop rather than through `supervision(...)`:

```python
# gone
CodingAgentTask(
    harness=ClaudeCodeHarness(capture="proxy", correction_channel=True),
    supervision_factory=supervision(model=..., transport=..., budget=3, ...),
)

# now
CodingAgentTask(
    harness=ClaudeCodeHarness(
        capture="stream",
        segmented=SegmentedSupervision(policy_factory=my_policy),
    ),
)
```

**This raises** at construction or import for every name above — except one
thing worth calling out: the paired control arm has no shipped replacement.
`CONTROL_BUDGET` was a budget of zero on a policy that still consulted the
judge at every boundary, which is what made the two arms matched on the
judging side. If you were running that comparison, you now own its
construction: build a `SegmentedSupervision` whose `policy_factory` returns a
`supervising_policy(budget=0, ...)` and keep every other argument identical to
the treatment arm's.

### 3. Run-record vocabulary that no longer has a writer (#450)

**What changed.** Three names went with the carrier that wrote them:

| Name | Was |
|---|---|
| `swe_lab.rollout.SUPERVISION_METRIC` (`supervision.unhealthy`) | 1.0 when a supervised run lost its supervisor with no bound on the loss |
| `swe_lab.rollout.SUPERVISION_LAPSE_METRIC` (`supervision.lapses`) | how many boundaries went unsupervised for a reason the policy could bound |
| `RolloutOutcome.SUPERVISION_FAILED` | the outcome the first of those produced |

The two native metrics — `supervision.stale` and
`supervision.max_decision_lag_seconds` — went with §1 for the same reason.

**Say it plainly: nothing can emit any of them any more, so no future record
will carry them.** `rollout_outcome` no longer has a branch that can return
`SUPERVISION_FAILED`, and it is no longer in the set of outcomes that are ours
rather than the actor's.

**Why.** An enum member nothing can produce is a name, not a contract.

**What you must do.** This is the quiet kind and the reason this note exists:
nothing raises when you keep reading them.

- **A reader that looks these metrics up with a default keeps working**, and
  will simply never see them again. That is fine, and it is also the trap: an
  arm that reports "0 lapses" for every 0.3.7 run reads exactly like an arm
  that had none.
- **A reader that branches on `RolloutOutcome.SUPERVISION_FAILED` still
  compiles** — the member is gone, so `getattr` and string comparison against
  `"supervision_failed"` both go quietly dead rather than failing. Delete the
  branch instead of leaving it unreachable.
- **Records written by 0.3.6 and earlier are unaffected** and still carry
  these keys. If you pool old and new runs, the absence is a version boundary,
  not a measurement.

### 4. `SegmentedSupervision` names its upstream with two strings (#448)

**What changed.** The `provider` field is gone, along with the module behind
it, and two strings the caller owns stand in its place:

```python
# 0.3.6
policy_factory: Callable[[int, Provider], SpeakPolicy]
provider: str = "anthropic"

# 0.3.7
policy_factory: Callable[[int, str, str], SpeakPolicy]
base_url: str = <default_supervisor_base_url()>   # a default_factory
api_key_env: str = "ANTHROPIC_API_KEY"
```

The loop calls it as `policy_factory(cooldown, base_url, api_key_env)`.
Removed whole: `swe_lab.trace_synthesis.provider` — `Provider`,
`ProviderError`, `build_provider`, `transport_for`, `live_key`, `Probe`, the
`ANTHROPIC` / `OPENROUTER` names and `OPENROUTER_API`. `messages_transport`
lost its `select_key` parameter, which had no caller left once the pool
sampler went. The definitions `SUPERVISOR_PROVIDER` and `SUPERVISOR_TRANSPORT`
are gone too; `SUPERVISOR_BASE_URL` remains and is now
`default_supervisor_base_url()`.

`__post_init__` no longer validates a name against a registry. It refuses
exactly one thing — an empty `api_key_env`, which can name no variable — and
that refusal still happens while the command line is read, so it costs a
construction rather than a container.

**Why.** 0.3.6 shipped a closed two-entry registry with no way to pass a
custom upstream: a consumer pointing at their own endpoint had to fork. It
also reversed a decision 0.3.2 had already made and written down. **These
names shipped in 0.3.6 and are removed one release later** — that is a second
breaking change to this seam in two days, and there is no softer way to put
it. `SegmentedSupervision.policy_factory` widened in 0.3.6 and widens again
here, so **a consumer upgrading 0.3.5 → 0.3.7 sees one change to that
signature, and one upgrading 0.3.6 → 0.3.7 sees a second.**

**What you must do.** Take the two strings and build the transport from them:

```python
import functools
from swe_lab.trace_synthesis.judge import messages_transport, supervising_policy

def my_policy(cooldown: int, base_url: str, api_key_env: str) -> SpeakPolicy:
  return supervising_policy(
      model=MY_MODEL,
      transport=functools.partial(
          messages_transport, base_url=base_url, api_key_env=api_key_env
      ),
      cooldown=cooldown,
      ...,
  )
```

and name an upstream per invocation with the two overrides:

```sh
--<rollout entry>.harness.segmented.base_url=https://openrouter.ai/api
--<rollout entry>.harness.segmented.api_key_env=OPENROUTER_LIVE_KEY
```

**Two-parameter factories raise, but they raise inside a run** — the loop
calls the factory once the sandbox is already up, and a callable's arity is
not checked before then. `provider=` on a `SegmentedSupervision` raises at
construction, and the removed `--…segmented.provider=` override is refused as
a bad argument.

`api_key_env` must name a variable holding **one** key. The library never
splits a pool: whoever knows the pool picks a live member and exports it,
which keeps every other key out of this process. `live_key`, which used to do
that here, is one of the names removed above.

### 5. The supervisor decision row renames its upstream column (#448)

**What changed.** `supervisor_provider` — added in 0.3.6, one release ago — is
replaced by `supervisor_base_url`, carrying the URL itself rather than a
registry label, because there is no registry to label from. It is written on
every row kind (`spoke`, `silent`, `lapse`, `gap`, `unjudged`), by the
segmented carrier, which is now the only carrier writing rows at all.

Its meaning is unchanged and is worth restating because it is easy to misread:
it is **the upstream this invocation was pointed at, not proof anything
answered.** A `lapse`, `gap` or `unjudged` row carries it too, and those are
exactly the rows where nobody did. No credential goes next to it — only the
key's variable *name* is ever configuration, and the value is read at call
time.

**What you must do.** Nothing raises. A reader keyed on `supervisor_provider`
will find `None` on every 0.3.7 row and, if it defaults, will silently
attribute every run to whatever its default is. Re-key it to
`supervisor_base_url`, and expect a URL where a label used to be — `"anthropic"`
and `"openrouter"` are not values this column takes any more.

### 6. `require_valid_guidebook` is gone, and the error it raised is renamed (#452, [ADR-0027](../decisions/ADR-0027-the-oracle-writes-a-guidebook-either-way.md))

**What changed.** In `swe_lab.trace_synthesis.guidebook`:

| 0.3.6 | 0.3.7 |
|---|---|
| `require_valid_guidebook(text)` | removed — nothing gates on shape |
| `GuidebookRejectedError` | `GuidebookMissingError`, and it means only absence |
| `validate_guidebook(text, *, require_rubric=False)` | `validate_guidebook(text)` — the rubric is required unconditionally |

`validate_guidebook` still returns the same list of human-readable problems;
what changed is that it now always requires the compact rubric (its one caller
is phase B, whose output contract includes it) and that **no caller acts on
the list**. The lenient mode had no caller left once phase C stopped
validating.

**What you must do.** Delete calls to `require_valid_guidebook`; if you want
its behavior, `if validate_guidebook(text): raise ...` in your own code.
Catching `GuidebookRejectedError` **raises an `AttributeError` at import or
attribute access**, so this one is loud. Passing `require_rubric=` is a
`TypeError`.

### 7. `build_oracle_prompt` requires a `resolved` flag (#452, [ADR-0027](../decisions/ADR-0027-the-oracle-writes-a-guidebook-either-way.md))

**What changed.**

```python
# 0.3.6
def build_oracle_prompt(instance, *, failure=STAGED_FAILURE) -> str
# 0.3.7
def build_oracle_prompt(instance, *, failure=STAGED_FAILURE, resolved: bool) -> str
```

Keyword-only and **required, deliberately not defaulted**: a default here is a
guess about what happened, and the brief's first sentence states it as fact.
The shipped input builders read it from the staged verdict through the new
`attempt_resolved(sb, failure)`; `oracle_prompt` and `produced_failure_prompt`
no longer ignore their sandbox argument.

`OracleAnalysisTask.outputs_valid` was removed as an override — see §9 for
what that does to a run.

**What you must do.** Pass `resolved=`. **This raises** (`TypeError`) at the
call.

## Behavior changes

### 8. The supervisor's upstream follows the agent's own environment (#448)

**What changed.** With nothing configured, the supervisor's model calls go to
`ANTHROPIC_BASE_URL` — falling back to the Anthropic API root when it is unset
— with the key under `ANTHROPIC_API_KEY`. Those are the same two variables
`claude -p` itself reads, which is the point: a sandbox that already exports
`ANTHROPIC_BASE_URL` for its actor has now, as of this release, also pointed
the supervisor at the same place. In 0.3.6 the default was a hard-coded root
that the environment could not move.

**The default is resolved when the plan is constructed**, which for the
shipped module-level definitions means when
`swe_lab.workflow.definitions` imports. A variable set after that does not
reach it. That is the contract, not an accident of import order: an upstream
is configuration of a run, fixed and recorded before the run starts, rather
than re-read mid-flight where two segments of one run could be pointed at
different places while their rows disagreed about which.

**What you must do.** Nothing raises, and this is the expensive kind if it
surprises you: **if you export `ANTHROPIC_BASE_URL` in the process that starts
a run, your supervisor's calls now go there and are billed there**, where in
0.3.6 they went to Anthropic regardless. Check that variable before your first
0.3.7 run, and read `supervisor_base_url` off the decision rows (§5) to
confirm where the invocation was actually pointed. Set the base URL explicitly
on the entry if you want it independent of the environment.

### 9. The guidebook schema stopped gating anything (#452, [ADR-0027](../decisions/ADR-0027-the-oracle-writes-a-guidebook-either-way.md))

**What changed.** There were two gates on the guidebook's *shape*, and both
are gone:

1. `OracleAnalysisTask.outputs_valid` required a schema-valid guidebook, so a
   guidebook that failed the label check failed the attempt and blocked every
   later entry of the chain;
2. the harness called `require_valid_guidebook` before launching the guided
   rollout — a second gate that would have blocked an imperfect guidebook even
   after the first was removed.

What is left in the harness is **presence, and nothing else**: an absent or
empty guidebook still raises `GuidebookMissingError` before the actor starts,
because a guided run with no guidebook is an unguided run wearing a guided
run's entry key, and the 2×2 reading would count it as the latter.
`guidebook.md` is still a *required declared output* of the Oracle task, so an
Oracle run that wrote nothing still fails on the baseline check.

Validity is now recorded rather than enforced: `guidebook.valid` (0.0 or 1.0)
and `guidebook.stages` on the metrics, and `guidebook_problems` — the list of
problems, verbatim — in the attempt record's `extra`. Phase C validates
nothing at all; it reads whichever representation the artifact carries.

**Why.** A live Oracle wrote a good guidebook whose stage 4 used `**Edits.**`
and `**Tests.**` instead of `**Actions.**` and `**Expected observations.**` —
labels the brief itself offers — and about fifteen minutes of paid agent time
was discarded over the word. An imperfect guidebook is worth more than no
guidebook.

**What you must do.** Nothing raises. Two things change downstream:

- **`guidebook_problems` in a record is now evidence, not a verdict.** In
  0.3.6 its presence meant the attempt had been failed; in 0.3.7 the attempt
  succeeded and the guidebook went on to be used. A reader that treats the key
  as a failure flag will now report failures that did not happen.
- **An imperfect guidebook reaches the guided rollout.** If you were relying
  on the gate to keep malformed guidebooks out of a sweep, filter on
  `guidebook.valid` yourself at read time.

### 10. The Oracle's brief branches on the graded verdict (#452, [ADR-0027](../decisions/ADR-0027-the-oracle-writes-a-guidebook-either-way.md))

**What changed.** The brief used to hard-code that the attempt being explained
had failed. It now reads `resolved` from the staged verdict and writes one of
two briefs. A failed attempt gets the old one: diagnose the decision that went
wrong, and teach the fork that resolves it. A **passed** attempt gets a
different one — find the steps that were *guessed rather than derived* (a
name, a placement, an interface choice nothing in the task statement forced,
which happened to be right) and make them deliberate, since a blind agent
repeating the task can guess differently. Neither brief has a refusal path.

The prose that names the prior actor moves with the branch, so no sentence of
the brief contradicts the verdict sitting beside it.

**Why.** `from_scratch_guided_trace` runs phase B whatever the blind verdict
was (ADR-0023 §2), so a single-premise brief was a claim the run could
contradict — and did. One live Oracle reproduced the grading three times, got
25/25, read a verdict saying `resolved`, correctly refused to invent a
failure, and then asked an operator how to proceed in a headless run where no
operator existed. It obeyed the brief, and the pipeline scored that as a
failure.

**What you must do.** Nothing, if you run the shipped chain. Two consequences
worth knowing:

- **A verdict that cannot be read now refuses the run before the agent
  starts** — absent, not JSON, or carrying no boolean `resolved` raises
  `SandboxError`, the same class of refusal as an input nobody staged.
  Defaulting instead would put a guess in the brief's first sentence and state
  it as fact.
- **Prompt hashes and golden briefs will not match**, for both branches.
- Whether the success branch actually elicits a useful guidebook **is not
  covered by any test** and can only be learned from a live run. ADR-0027 says
  so; this note repeats it rather than letting the section read as a result.

### 11. Retry no longer fires on a schema result, and is dormant by default (#452, [ADR-0027](../decisions/ADR-0027-the-oracle-writes-a-guidebook-either-way.md))

**What changed.** `OracleAnalysisTask.should_retry` lost its schema clause.
What remains is the baseline — a run that ended anything but `SUCCESS`, or
produced no guidebook at all — plus the harness's own retryable endings: a
container that would not start, a network failure, a crash. Endings that
happened *to* the agent, in other words, and never a judgement about what it
wrote.

**The shipped entries carry no retry budget.** Every entry carrying this task
runs at the default `retries=0`, so `run_task` runs one attempt and the policy
above only decides whether to break out of a loop that has already ended: **by
default, an Oracle run is never retried, whatever happened to it.**

**Why.** A guidebook that fails a label check is not bad luck, it is what the
model wrote; re-running buys another sample of the same writer at the price of
a paid agent run. The `retries=0` half is a decision about spending someone
else's quota, not a claim that those endings are unworthy of another attempt.

**What you must do.** If you want retries on an Oracle entry, ask for them per
run — `--oracle_analysis.retries=N`, which reaches the entry field — and you
then get this policy instead of the base class's. Nothing raises either way.

### 12. A forged criterion is now refused after the sandbox is up, not before (#450)

**What changed.** `supervising_policy` still loads and digest-checks the
pinned criterion, and still refuses a forged one. *When* moved with the
carrier: the correction channel built its policy while a rollout assembled its
observers, so a forgery was refused **before a sandbox existed**. The segment
loop calls its `policy_factory` inside the run, so a forgery now stops the run
**after** the container is up.

**The refusal is unchanged; the cost of it is a container.** This is written
down rather than quietly dropped because the trace-synthesis spec used to
claim the earlier timing, and a silently removed claim cannot be told apart
from one never made.

## Added

Small, and all of it in service of the changes above.

- `swe_lab.trace_synthesis.judge.default_supervisor_base_url()` — the upstream
  a supervisor is pointed at when nobody says, with `ANTHROPIC_BASE_URL_ENV`
  and `DEFAULT_API_KEY_ENV` naming the two variables. It reads the environment
  when it is *called*, and the caller decides when that is (§8).
- `swe_lab.trace_synthesis.oracle.attempt_resolved(sb, failure)` — reads the
  staged verdict's `resolved` flag, off the same bytes the Oracle itself will
  read (§10).
- `swe_lab.trace_synthesis.guidebook.GuidebookMissingError` — absence, and
  only absence (§6, §9).

## Verified

- **A live paid run of the full chain, on this code, green end to end for the
  first time.** Sweep `fs1`, one SWE-bench Pro instance
  (`internetarchive__openlibrary-5de7de19…`), one rollout, supervised through
  OpenRouter. All five entries of `from_scratch_guided_trace` succeeded:
  blind rollout → graded `unit_test.resolved = 0.0` → Oracle wrote a guidebook
  (`guidebook.present 1.0`, `guidebook.stages 5.0`, **`guidebook.valid 0.0`**)
  → guided rollout → graded `unit_test.resolved = 1.0`.
  `swe-lab guided-gain fs1` reads `gained: 1` (`kept 0, regressed 0,
  unsolved 0`, 0 incomplete). Read by this note's author from the run's own
  `workflow.json` and attempt records, and by re-running `guided-gain` against
  the store.
- **The guidebook that solved the instance is one the old schema would have
  rejected.** Its `guidebook_problems` are `stage 4: missing the 'Actions'
  field` and `stage 4: missing the 'Expected observations' field` — the same
  two ADR-0027's earlier run r0 was blocked on. That the run is on post-#452
  code is not read off a timestamp: the record carries `guidebook.valid 0.0`
  *and* `outputs_valid: true`, which 0.3.6's `outputs_valid` override made
  impossible, and the guided rollout ran at all, which 0.3.6's
  `require_valid_guidebook` gate would have stopped. That is the single
  clearest statement of what §9 changed. **Do not overstate it: n=1** — one
