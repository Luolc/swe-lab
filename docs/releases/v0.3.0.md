# v0.3.0 — 2026-09-02

The release that turns supervised rollouts from a design into something a
command can start. A supervisor watches the actor's live output stream and can
write a correction on its stdin mid-run; the first end-to-end supervised
rollout has been run once, and what that does and does not establish is stated
in the handoff note,
[`docs/trace-synthesis/downstream-scale-note.md`](../trace-synthesis/downstream-scale-note.md)
— read it before scheduling a batch, and read it rather than inferring status
from this file.

For a consumer running rollouts, **the expensive changes here are not the new
feature.** Three things break a working setup, and two more change what an
unchanged command produces: run outputs moved, the host-side capture proxy is
gone, the SWE-Bench Pro parquet is now hash-verified on every load, the patch
baseline default flipped, and the agent's per-attempt timeout doubled.

Minor bump rather than patch: public names were removed.

Raw commit list: the GitHub Release's generated notes.

---

## Breaking

### 1. A run's output directory gained an `r<rollout_id>` segment, and its root is now a flag (#332)

**What changed.** The default location of a run's outputs:

```
.cache/runs/<workflow>/<instance_id>              # v0.2.14
<output-root>/<workflow>/<instance_id>/r<rollout_id>   # v0.3.0
```

`--output-root` is new and defaults to the old `.cache/runs` under the repo
root, so the *root* is unchanged unless you pass it; the `r<rollout_id>`
segment is unconditional.

Scope, precisely: this is the **throwaway** store and the run's scratch
directory. The shared T1 store that `--persist` selects is unchanged — its
keys and layout did not move.

**Why.** The scratch directory is wiped on a non-resumed run, and it was keyed
by workflow and instance only. Running `--rollout-id 0` then `--rollout-id 1`
sequentially therefore left only the second record, while the first run's own
output had already reported `"succeeded": true` and the `record_key` it wrote.
`--rollout-id` is the declaration that two runs are two samples rather than a
repeat, so it belongs in the key.

**What you must do.** This applies to one kind of reader only: **if you
construct a path into the scratch / throwaway output directory**, add the
`r<rollout_id>` segment. A consumer reading the shared T1 store through
`--persist` must **not** — those keys did not move, and adding the segment
there would break a reader that works today.

For the readers it does apply to, ignoring it fails two different ways, and
**only one of them is loud.** On a machine with no v0.2.14 leftovers, a path
built the old way is simply absent and the read raises. On a machine that
**still has a v0.2.14 output directory on disk**, that directory is untouched
at the old path — so the same unchanged construction keeps succeeding and
hands back the *previous* run's record. Nothing raises, nothing is logged, and
a whole batch can be read, graded and reported as a success while every record
in it came from before the upgrade. **The absence of an error is not evidence
that you migrated.** Delete or move the legacy directories before the first
v0.3.0 run rather than relying on a read to fail.

Separately, and worth doing at the same time: pass `--output-root` to
somewhere outside the checkout. The default is inside it, and
`git worktree remove` deletes gitignored content silently — this repo has
already lost a run's only record that way.

### 2. The host-side capture proxy is gone; `PROXY` capture runs inside the sandbox (#264, [ADR-0012](../decisions/ADR-0012-in-sandbox-capture-proxy.md))

**What changed.** Public names removed, with no deprecation period:

| Gone | Replacement |
|---|---|
| `ClaudeCodeHarness.proxy_port`, `.proxy_base_url` | `ClaudeCodeHarness.proxy_target: str` — the upstream to forward to |
| `ClaudeCodeHarness.agent_proxy_url()` | nothing; the in-sandbox proxy listens on a fixed loopback port (`constants.PROXY_PORT`) |
| `harnesses.claude_code.recorder` (module) and its `ProxyRecorder` | nothing to import; the harness composes the proxy itself |
| `proxy.build_proxy()`, `proxy.ReverseProxy`, `proxy.port_for_index()`, `proxy.DEFAULT_BASE_PORT` | nothing; there is no host-side listener to build or to allocate a port for |
| `constants.CONTAINER_PROXY_HOST` | nothing |

`proxy.proxy_binary_path()` also changed signature — it now takes `version`
and `build` alongside `repo_root`.

One container-level consequence, which is not an import error and so is worth
more words: containers are **no longer created with
`--add-host host.docker.internal:host-gateway`**. Nothing in the sandbox can
reach the host by that name any more.

**Why.** The host-side scheme needed a port per concurrent run, a firewall
rule, and on this machine a tailnet exposure — all to carry traffic that never
had to leave the container.

**What you must do.** Constructing `ClaudeCodeHarness` with `proxy_port=` or
`proxy_base_url=` now **raises** `TypeError` (it is a frozen dataclass), and
importing the `recorder` module **raises** `ModuleNotFoundError`; both fail
loudly, so neither can silently do the wrong thing. Replace the two fields
with `proxy_target` if you were pointing capture at a non-default upstream,
and drop any host-side port allocation, firewall rule or `host.docker.internal`
dependency in your own composition.

### 3. The SWE-Bench Pro parquet is verified against a pinned sha256 on every load (#345)

**What changed.** `load_dataset("swebench_pro")` now runs
`datasets.swebench_pro.fetch.ensure_swebench_pro_parquet` before reading. It
does not download — the manual `curl` step in
`datasets/swebench_pro/README.md` is unchanged — it verifies:

- the file must be present under exactly `test-00000-of-00001.parquet`
  (`constants.PARQUET_FILENAME`); a `.parquet` present under another name
  raises `FileNotFoundError` naming what it did find;
- its sha256 must equal `constants.PINNED_SWEBENCH_PRO_PARQUET_SHA256`
  (`c8cd7115…13f8`, 7,816,820 bytes), or it raises `ValueError`.

**Why.** The loader previously accepted whatever bytes were on disk under that
name, so a truncated download, an upstream file that drifted, and a stale copy
from before a deliberate pin bump were all indistinguishable from the real
thing. What the pin proves is narrow and worth stating: the local copy is
byte-identical to what Hugging Face's own LFS record serves for
`ScaleAI/SWE-bench_Pro` (both checked on 2026-09-02, independently of each
other). It does **not** establish that the published file is the one any
paper's numbers came from.

**What you must do.** Verify your local copy before your first v0.3.0 run:

```sh
sha256sum datasets/swebench_pro/data/test-00000-of-00001.parquet
# must equal PINNED_SWEBENCH_PRO_PARQUET_SHA256
```

A mismatch or a renamed file **raises on every load**, so nothing runs against
an unverified dataset. Re-download per the dataset README rather than editing
the pin. This is the first thing a stale environment will hit.

## Behavior changes (nothing moved — but an unchanged command produces something different)

### 4. The pre-agent baseline is now the default on both halves (#326, [ADR-0014](../decisions/ADR-0014-the-pre-agent-baseline-is-the-default.md))

**What changed.** `CodingAgentTask.patch_baseline` and
`UnitTestTask.patch_baseline` both flipped `False` → `True`. The patch is
taken against the tree **as the agent found it**, committed before the agent
starts, and the rollout record carries `extra["patch_base_ref"]`; grading
recomputes that baseline and verifies the sha before applying.

**Why.** Some images ship files untracked at `base_commit` — one SWE-Bench Pro
image carries a Redis append-only-file directory — and against `base_commit`
that yields a 166 KB patch from a run in which no agent executed at all. How
many instances are affected is **not measured**; one image was examined.

**What you must do.** This one **silently does something different** rather
than raising: the same instance, the same actor and the same command can now
produce a different patch, so results are not comparable across the version
boundary on affected instances. Two consequences: re-baseline rather than
compare, and note that the two halves must stay set together (each alone moves
the patch and the tree apart). `patch_baseline=False` still exists — set it
only to reproduce a pre-ADR-0014 run, or for a patch whose base genuinely
*is* `base_commit`, which is what `gold_unit_test` and `datasets/verify.py`
do.

### 5. The agent's per-attempt timeout doubled: 1800 s → 3600 s (#267)

**What changed.** `_AGENT_TIMEOUT_S` in `workflow/definitions.py`. The grading
suite's budget is unchanged at 1800 s.

**Why.** Set against a p90 rollout wall clock of about one hour measured by
the owner outside this repo (2026-09-01); at 1800 s a real slice of healthy
runs was killed mid-solve, and a killed run reports as an infrastructure
failure rather than as the reasoning failure it was on its way to being.

**What you must do.** Re-do wall-clock and cost planning for a batch: this is
**per attempt, not a budget shared across retries** — `run_task` passes the
same value into every iteration of `range(retries + 1)` — so the worst case
per rollout scales with the retry count. Nothing raises; a batch simply takes
longer and costs more than the same batch on v0.2.14 would have.

### 6. An attempt whose ending was *ours* is no longer graded, and a run that cannot show its record fails (#338, #332)

**What changed.** Two independent refusals:

- `CodingAgentTask.outputs_valid` now returns `False` when
  `rollout_outcome(result).ours` — an out-of-memory kill, an engine or harness
  failure, or a lost supervisor. A workflow blocks every later entry once an
  entry fails, so grading does not run at all for those. An ending the
  **actor** owns — a spent wall clock, or a clean run with no patch — is not
  refused here.
- The `run` command reads its own `record_key` back from the store before
  printing the summary, and exits `FAILED` when it cannot.

**Why.** For the first: a run whose agent died in 1.4 s still spent the full
grading budget, and the damage could only be reported as a zero. For the
second: a summary saying `"succeeded": true` next to a `record_key` is a claim
about the filesystem, and a wiped directory, a failed write, a mis-joined key
and a full disk all produce the same successful-looking output.

**What you must do.** Expect runs that previously produced a graded zero to
now stop at the rollout stage with no grading entry, and expect a non-zero
exit where a summary was previously printed. Both are the intended reading —
an infrastructure failure is no longer counted as task difficulty — but a
harness that treats "no grading entry" or "non-zero exit" as a crash needs to
learn the difference. Use `extra["rollout_outcome"]` to tell them apart — see
[Added](#added) for the field and
[ADR-0016](../decisions/ADR-0016-the-endings-nobody-could-attribute.md) for
how to read it.

### 7. Containers are labelled with their owner, and a spawned command's whole process tree is ended (#288, #290)

**What changed.** The host backend labels every container with
`swe-lab-owner-pid` and `swe-lab-owner-session` at `create` (a session uuid,
because pids are reused), and owns it from `create` rather than from `start`,
so a failure between the two removes it. Command teardown ends the process
group rather than just the direct child.

**What you must do.** Nothing, unless you reap swe-lab containers yourself —
in which case the labels are what to match on, and a container can now exist
in `created` state briefly before `start`.

## Added

- **`RolloutOutcome`, and a rate that carries its two counts** (#329, #338,
  #339; [ADR-0015](../decisions/ADR-0015-four-words-for-how-a-rollout-ends.md),
  [ADR-0016](../decisions/ADR-0016-the-endings-nobody-could-attribute.md)).
  The enum did not exist in v0.2.14. Seven members — `OOM_KILLED`,
  `SYSTEM_FAILED`, `TIMED_OUT`, `NO_PATCH`, `PATCH_PRODUCED`, `UNCLASSIFIED`,
  `SUPERVISION_FAILED` — recorded verbatim in the rollout record's
  `extra["rollout_outcome"]`, with `.ours` deciding both whether grading runs
  and whether the run counts in a denominator. **If you consume that field,
  read ADR-0016 first**: it supersedes ADR-0015's taxonomy and its reporting
  rule. `swe_lab.reporting.Rate` is the one renderer for a rate and its two
  counts (`resolved 12 / 40 (3 system failures excluded, 2 unclassified)`).
- **The rollout record says who ran and what it cost.** `extra["agent_model"]`,
  plus `agent_cost_usd` / `agent_num_turns` where the harness's trace carries
  them (`Harness.usage()`, defaulting to empty rather than to zero). The
  record's top-level `model` field stays empty by design — look in `extra`.
- **Supervised rollouts.** The `trace_synthesis` package (supervisor, judge,
  writer, speak policies, criterion, guidebook, oracle) and three new
  workflows: `supervised_rollout_and_unit_test`, its paired
  `control_rollout_and_unit_test` (the same code path with the speaking budget
  at zero, so the arms differ only in whether a correction is delivered), and
  `oracle_analysis`. No existing workflow was renamed or removed. Two things
  the arms need that nothing else does: a provider key in
  **`OPENROUTER_API_KEYS`** (comma-separated; `openrouter_transport` raises
  `RuntimeError` without one) and `ClaudeCodeHarness(correction_channel=True)`
  with `capture="proxy"`, which the shipped definitions already set. Composing
  supervision onto a harness that cannot receive a correction raises
  `ValueError` at construction rather than running silently unsupervised.
- **`ClaudeCodeHarness.correction_channel`** (default `False`) and
  `Harness.accepts_corrections` (default `False`) — both additive, so an
  existing harness implementation needs no change.
- **The actor's own native session transcript is collected** before the
  container dies (#351) — `claude_code.native_transcript.tar.gz`, written by
  Claude Code for its own resume, which makes it evidence that does not come
  through swe-lab's own collection path.
- **The `oracle_failures` dataset** (#275): a cached rollout failure, runnable
  as its own dataset, so trace synthesis can start from a known failure
  instead of re-earning one.
- **Redaction and a publication gate** (#278, #283): header and body redaction
  converged onto one home, `publication_blockers()` / `unclassified_fields()`
  over a proxy log, and the annotation pipeline refuses to publish a record
  that still carries something private.
- **`--output-root`** (see
  [Breaking §1](#1-a-runs-output-directory-gained-an-rrollout_id-segment-and-its-root-is-now-a-flag-332))
  and a repo-scoped host OAuth variable
  (#256, #257): `.envrc.local` exports `SWE_LAB_CLAUDE_CODE_OAUTH_TOKEN`, and
  the CLI copies it to the canonical name for its own process only. A local
  convenience, not a contract — CI and the sandbox still know one name, and an
  already-set canonical variable is left alone.

## Verified

- Quality bar on the release commit: `pre-commit run --all-files` clean (all 8
  hooks), `pytest -m 'not docker'` **967 passed, 4 skipped, 10 deselected**.
  Of the 4 skips, one is the dataset test on a checkout without the parquet
  and three are workflow-yaml tests whose workflows pass no CLI overrides; the
  10 deselected are the docker-marked set, which CI runs.
- **One** end-to-end supervised rollout, on one SWE-Bench Pro instance, against
  criteria frozen before the run: all seven acceptance points closed. The
  readings, and what a single run does not establish, are in
  [`downstream-scale-note.md`](../trace-synthesis/downstream-scale-note.md)
  and the report it links. **No batch and no sweep was run for this release**,
  and no effect of supervision is claimed or measured.
- The pinned parquet's digest was checked against two independent sources on
  2026-09-02 (a local download, and Hugging Face's own LFS record), which
  agreed on both the digest and the byte size.
