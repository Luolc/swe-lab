# v0.3.2 — 2026-09-03

## The supervisor speaks Anthropic, and names no provider

`0.3.1` shipped a supervisor that spoke OpenAI chat-completions to OpenRouter.
Nobody had chosen that: OpenRouter was convenient to test against, and the
convenience hardened into code — `OPENROUTER_API`, `OPENROUTER_ENDPOINT`,
`OPENROUTER_KEYS_ENV` and `openrouter_transport` were all named after a provider
that was never a decision. A consumer standing up its own gateway may have no
OpenAI chat format at all.

Both supervisor paths now speak the **Anthropic Messages API**, and what the
supervisor needs is exactly three values: **a base URL, an API key, and a
model**.

### Breaking

If you configure supervision, all of this changes at once.

- **Wire format is `/v1/messages`, not `/v1/chat/completions`.** `system` is a
  top-level field rather than the first message; `messages` carries only user
  and assistant turns; requests send an `anthropic-version` header; replies are
  read from `content[0].text`; the stop reason is `stop_reason`, not
  `choices[0].finish_reason`.
- **Authentication is `x-api-key`, not `Authorization: Bearer`.** The supervisor
  calls the API directly and therefore cannot use the actor's OAuth
  subscription token — it needs an API key of its own. The actor's OAuth path is
  unchanged.
- **`OPENROUTER_API_KEYS` is gone.** The supervisor reads `ANTHROPIC_API_KEY` by
  default; `SWE_LAB_SUPERVISOR_API_KEY_ENV` selects a different variable *name*.
  That selector is validated as a portable environment-variable name and an
  explicitly empty value is refused rather than silently falling back.
- **`SUPERVISOR_MODEL` is `claude-sonnet-5`**, not `anthropic/claude-sonnet-5`.
  The model is an opaque string: nothing validates it, translates a slug, or
  branches on a provider. Point the base URL wherever you like and pass whatever
  name that endpoint expects.
- **`SWE_LAB_SUPERVISOR_BASE_URL` no longer has `/chat/completions` appended.**
  The in-sandbox binary now appends the Messages path.
- **No provider name survives in the code.** `OPENROUTER_API`,
  `OPENROUTER_ENDPOINT`, `OPENROUTER_KEYS_ENV` and `openrouter_transport` are
  deleted rather than made configurable.

### Which path needs a proxy — the distinction that was implicit before

- **The Python host-side supervisor — the default, and what
  `oracle_guided_trace` and `segmented_rollout_and_unit_test` use — needs no
  proxy at all.** It runs on the host and reaches a non-loopback HTTPS endpoint
  directly. A base URL, an API key and a model are the whole configuration. This
  is pinned by a test that captures the emitted URL, body and headers, rather
  than one that merely constructs a transport.
- **The in-sandbox Rust runtime (native supervision) still requires a loopback
  forwarder**, because the binary carries no TLS. Its refusal of `https://`, of
  hostnames, and of any non-numeric or non-loopback address is unchanged and
  deliberate: it sends a bearer credential in clear to something inside the
  sandbox. Its proxy target, port, key-variable and log names are now
  configurable instead of constants.

If you bring your own gateway and do not run `cc-reverse-proxy`, use the Python
path.

### Fixed

- **A credential could reach `summary.unclean_reason` and stderr.** The API-key
  *variable selector* was interpolated unvalidated into a refusal diagnostic: a
  caller who put the key itself there by mistake would have written it verbatim
  to both outlets. The selector is now validated and never rendered. Sentinel
  tests cover both outlets.
- **`n_batching_replay`'s self-check reported success while doing nothing.** The
  driver still indexed the old second chat message and parsed `choices`, so
  every call raised `IndexError` before reaching the transport and the equality
  check compared two all-gap runs — exiting 0 while reporting `0 prompts
  byte-identical`. It now replays through the Messages shape (`169 prompts
  byte-identical`) and fails when the call count is zero. Its committed
  artifacts remain labeled as historical observations of the old channel.

### Unchanged from 0.3.1

The gaps `0.3.1` shipped with are still open: `max_cost_usd` does not cap
cumulative spend (#419), the `oracle_failures` builder refuses runs produced by
the default `patch_baseline=true` (#416), segmented cooldown is not overridable
(#415), and a missing or malformed guidebook is still not rejected at the seam.
