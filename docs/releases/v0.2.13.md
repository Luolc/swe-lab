# v0.2.13 — 2026-08-25

**Nothing breaks, but this is a big one**: patch extraction and grading now
support **two styles, end to end** — the classic `base_commit` round trip
(unchanged, still the default) and an opt-in **pre-agent baseline** for task
images whose worktree ships already different from `base_commit`
([#231](https://github.com/Luolc/swe-lab/issues/231)). If you touch neither
flag, nothing about your runs changes; the default eval script is
byte-identical with the flag off, by test.

Raw commit list: the GitHub Release's generated notes.

## Added — the pre-agent baseline, as a pair of flags

Some task-image formats ship worktrees with build-time edits that were never
committed. Diffed against `base_commit`, those edits fold into **every**
agent's patch — an agent that changed nothing still produces a large patch,
and grading fails identically across agents in a way that reads as
infrastructure. ADR-0001 had deferred the fix with a named revisit condition;
#231 met it, and the design landed as a dated amendment.

- `CodingAgentTask.patch_baseline` — before the agent starts (and after the
  history purge, an ordering now pinned by test), commit the tree exactly as
  found, with pinned identity/dates/message; diff the **worktree** against
  that. Worktree, not `baseline..HEAD`: it captures uncommitted edits *and*
  commits, where commit-to-commit silently yields an empty patch if the agent
  never commits.
- `UnitTestTask.patch_baseline` — the grading half, and **the two must be set
  together**. A `BaselineVerifyObserver` recomputes the baseline with the same
  pinned commands (one source: `git/patch.py:baseline_commit_lines`), and the
  sha — a pure function of the image's tree — must equal the run's recorded
  base: equality *proves* the grading container holds the tree the patch was
  taken from. Only then does it reset (to the baseline, not `base_commit`) and
  let the script apply and grade.
- The base ref travels as an artifact (`patch.base_ref.txt`, captured before
  the agent could touch it) over the same workflow edge as the patch, and is
  recorded on the attempt as `patch_base_ref` — in **both** modes, so a record
  always says which base produced its patch.

**Attribution is the design's spine.** A tree mismatch **fails the run
ungraded** (`setup_error`, both shas named in the recorded error) — it is an
environment fault, and the first implementation, which scored such runs
`resolved = 0.0` *succeeded*, was caught by this release's own e2e gate and
fixed before shipping. A patch that fails to `git apply` still grades
unresolved: that one is the patch's fault, and stays Scale-aligned.

## For downstream `TaskInstance` implementers

`TaskInstance.unit_test_spec` gained a defaulted `patch_baseline` kwarg.
`UnitTestTask` passes it **only when set**, so an implementation written
before the kwarg existed keeps working untouched — until its dataset opts into
baseline grading, at which point implementing the parameter is the work
anyway.
